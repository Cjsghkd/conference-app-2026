# NavKey serializer aggregation (NavKeySerializersProvider)

Each feature registers the serializers for its own `NavKey`s, and app-shared merges them into the single `SerializersModule` the back stack needs — with the per-feature registration generated by KSP.

## Why aggregate

Navigation3's back stack is a list of `NavKey`s that must be **serialized to save and restore it** across configuration changes and process death: `rememberNavBackStack` requires a `SavedStateConfiguration` whose `SerializersModule` covers **every `NavKey` in the app**. But `NavKey`s live in separate feature modules, and a sealed hierarchy cannot span modules — so each key has to be registered open-polymorphically, and a key that is missing from the module **crashes at runtime the moment the back stack is saved** with that key on it.

To keep that registration from depending on anyone remembering to edit a central file, each feature **contributes the polymorphic serializers for its own `NavKey`s**, and app-shared merges them into the single `SerializersModule` that `KaigiApp` passes when it builds the back stack.

## How: contribute and merge

```kotlin
interface NavKeySerializersProvider {
    val serializersModule: SerializersModule
}

@Inject
@SingleIn(AppScope::class)
class MergedNavKeySerializersProvider(providers: Set<NavKeySerializersProvider>) : NavKeySerializersProvider {
    override val serializersModule: SerializersModule = SerializersModule {
        providers.forEach { provider ->
            include(provider.serializersModule)
        }
    }
}
```

Each provider registers its keys via `polymorphic(NavKey::class) { subclass(TimetableNavKey::class, TimetableNavKey.serializer()) }` and lands in the set through `@ContributesIntoSet(AppScope::class)`.

## Why KSP generates the provider

The per-feature provider is pure boilerplate — enumerate the module's `NavKey` subclasses and register each one — and hand-writing it reintroduces the exact gap the aggregation exists to close: forgetting to add a new key. So `:tools:ksp-processor` scans each feature module for `NavKey` subclasses and emits its `…NavKeySerializersProvider`. It is wired in the `droidkaigi.convention.kmp-feature` [convention plugin](./build-convention-plugins.md) (`add("kspCommonMainMetadata", project(":tools:ksp-processor"))`, with the generated sources added to `commonMain`), so **adding a `NavKey` automatically registers its serializer**.

A useful side effect: the generated code references each key's companion `.serializer()`, so a `NavKey` missing `@Serializable` **fails to compile** instead of crashing at back-stack save time — enforcement without a custom checker.

Codegen stops here — each feature's `NavEntryProvider` and `Default…Navigator` are deliberately hand-written (a few lines each).
